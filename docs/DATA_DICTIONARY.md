# Data dictionary

Generated from the dbt `schema.yml` and `sources.yml` files by
`scripts/gen_data_dictionary.py` (`make docs`). Do not edit by hand.
For lineage, open the dbt docs (`make docs`, then `/dbt-docs/` on the API).

## Bronze: raw sources

### `bronze.boc_valet`

Raw Bank of Canada Valet observations (policy rate, CORRA, bond yields, FX).

| Column | Description |
| --- | --- |
| `series_key` | Platform series key (see config/series.yaml). |
| `source_id` | Valet series name, for example BD.CDN.10YR.DQ.YLD. |
| `obs_date` | Observation date as text (YYYY-MM-DD). |
| `value_raw` | Observation value as text, null when the source returned no value. |
| `load_id` | Identifier of the extract run that wrote the row. |
| `loaded_at` | UTC time of the extract run. |
| `source_url` | Exact URL that was requested. |

### `bronze.statcan_wds`

Raw Statistics Canada WDS data points for CPI table 18-10-0004-01.

### `bronze.load_log`

One row per series per extract run with row counts, date range and source URL.

### `bronze.series_catalog`

The series catalog from config/series.yaml, written by the pipeline.

### `bronze.calendar`

Bank of Canada business-day calendar generated by cmdp.calendar.

## Silver: cleaning and checks

### `silver.int_observations_flagged`

Every bronze row from both sources with its cleaning decision. Rule 2: rows whose value is empty or not numeric get `removal_reason = 'null_value'`. Rule 3: when a (series, date) pair arrives more than once, the latest load is kept and older copies get `removal_reason = 'duplicate'`. Row count equals the bronze row count.

| Column | Description | Tests |
| --- | --- | --- |
| `series_key` | Platform series key. | `not_null` |
| `obs_date` | Observation date. | `not_null` |
| `version_rank` | 1 for the latest load of a (series, date, is-null) group. |  |
| `removal_reason` | Null when kept, otherwise `null_value` or `duplicate`. | `accepted_values` |

## Gold: data quality models

### `gold.dq_freshness`

Freshness per series: business days between the latest observation (or, for monthly series, the end of the reference month) and the as-of date. Status is green within the threshold (5 business days for daily series), amber within twice the threshold and red beyond.

Model tests: `dq_freshness__policy_rate`, `dq_freshness__money_market`, `dq_freshness__bond_yield`, `dq_freshness__fx`, `dq_freshness__cpi`

| Column | Description | Tests |
| --- | --- | --- |
| `series_key` | Platform series key. | `unique`, `not_null` |
| `category` | Series category. |  |
| `frequency` | daily or monthly. |  |
| `threshold_business_days` | Maximum allowed age in business days. |  |
| `latest_obs_date` | Latest observation date. |  |
| `period_end` | Date the age is measured from (month end for monthly series). |  |
| `as_of_date` | Reference date of the check (today, or the last fixture date offline). |  |
| `business_days_since` | Business days after period_end up to and including as_of_date. |  |
| `is_fresh` | business_days_since <= threshold_business_days. |  |
| `status` | green, amber or red. | `accepted_values` |

### `gold.dq_completeness`

Completeness per series: expected periods (Bank of Canada business days or months) between the first and last observation, missing periods and the completeness percent.

| Column | Description | Tests |
| --- | --- | --- |
| `series_key` | Platform series key. | `unique`, `not_null` |
| `category` | Series category. |  |
| `frequency` | daily or monthly. |  |
| `first_date` | First observation. |  |
| `last_date` | Latest observation. |  |
| `expected_periods` | Business days (daily) or months (monthly) between first and last date. |  |
| `missing_periods` | Expected periods without an observation. |  |
| `completeness_pct` | 100 x (expected - missing) / expected. | `dq_range__completeness_pct` |

### `gold.dq_anomalies`

Observations whose day-over-day change exceeds 5 standard deviations of the previous 250 daily changes (series with anomaly_check = true). These are flags for review, not errors: a policy decision or a market shock can legitimately cause one.

Model tests: `dq_anomaly__money_market`, `dq_anomaly__bond_yield`, `dq_anomaly__fx`

| Column | Description | Tests |
| --- | --- | --- |
| `series_key` | Platform series key. |  |
| `category` | Series category. |  |
| `obs_date` | Date of the flagged move. |  |
| `value` | Value on that date. |  |
| `change` | Day-over-day change. |  |
| `sd_window` | Standard deviation of the previous 250 daily changes. |  |
| `z_score` | change / sd_window. |  |
| `sigma_threshold` | Threshold in standard deviations (5). |  |
| `window_size` | Number of previous changes used (250). |  |

### `gold.dq_reconciliation`

Row counts per series across layers. Load log rows must equal bronze rows; bronze rows must equal silver rows plus documented removals (null values, duplicates); silver rows must equal fact rows.

| Column | Description | Tests |
| --- | --- | --- |
| `series_key` | Platform series key. | `unique`, `not_null` |
| `load_log_rows` | Rows recorded in the bronze load log. |  |
| `bronze_rows` | Rows in the bronze Parquet files. |  |
| `silver_rows` | Rows in the silver table. |  |
| `removed_null_value` | Rows removed because the value was empty or not numeric. |  |
| `removed_duplicate` | Rows removed because a newer load had the same series and date. |  |
| `fact_rows` | Rows in fct_observation. |  |
| `diff_load_log_vs_bronze` | load_log_rows - bronze_rows (must be 0). | `dq_reconciliation__load_log_vs_bronze` |
| `diff_bronze_vs_silver` | bronze_rows - silver_rows - removals (must be 0). | `dq_reconciliation__bronze_vs_silver` |
| `diff_silver_vs_fact` | silver_rows - fact_rows (must be 0). | `dq_reconciliation__silver_vs_fact` |
